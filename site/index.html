01 — principles

Python-shaped code, without the mutation.

Everything you can mutate in Python is a compile error here. What is left reads like Python and behaves like Erlang — the compiler is strict, the runtime is Erlang's.

01 / immutability

Rebinding, not mutation.

No for, no while, no +=, no assignment to an index or attribute. Rebinding a name is allowed, and the compiler gives it a fresh Erlang variable — exactly the way Gleam does it.

loops.ee compile error 
1for x in xs:        # no loops
2    total += x       # no mutation
3
4total = total + 1  # rebinding: X@1 = X + 1
02 / expressions

Branches produce a value.

if and match are expressions: every branch ends by assigning the same variable, and that assignment is the result. The compiler checks the shape, so a branch cannot quietly return nothing.

fib.ee 
1def fib(n):
2    match n:
3        case 0:
4            r = 0
5        case 1:
6            r = 1
7        case _:
8            r = fib(n - 1) + fib(n - 2)
9    r
03 / failure

Let it crash.

A match that matches nothing raises {case_clause, V} in the process, like Erlang — not a returned error code. Exhaustiveness is a suggestion, not a requirement: Gleam refuses to compile such code, squeal lets the process fail.

eshell
11> shapes:shift(nope, 3).
2** exception error: no case clause matching nope
3     in function  shapes:shift/2 (src/shapes.ee:6)
04 / values

Quotes decide the type.

'ok' is an atom, "ok" is a UTF-8 binary. True becomes true, None becomes nil, tuples and lists keep their Erlang shapes, and dicts become maps.

values.ee
1def pair():
2    ('ok', "ok", True, None, {'k': 1})
3
4# {ok, <<"ok">>, true, nil, #{k => 1}}

02 — language

Six things worth knowing before you write a line.

The syntax is stock CPython 3.15 — no new grammar, no macros, no build step beyond the compiler. Which means your editor already knows how to indent it.

Classes are tagged tuples

A class with an atom payload compiles to a tuple tagged with its snake_case name — and its constructor is inlined, not called.

class Point(StartingWithAtom):
    x: int
    y: int

# Point(1, 2) → {point, 1, 2}

Patterns, everywhere

Destructuring assignment, constructor patterns, guards and or-patterns compile to the same Erlang patterns Gleam emits.

head, *rest = xs

match p:
    case Point(x, y) if x > 0:
        q = Point(x, y)

Comprehensions, 1:1

List and dict comprehensions map onto Erlang list and map comprehensions, filters and nesting included.

[x * 2 for x in xs if x % 2 == 0]
# [X * 2 || X <- squeal_iter(Xs), …]

Hierarchical modules

The module is the path: src/a/b/c.ee becomes a@b@c. Imports are Python imports with the same rules as Gleam.

from my.app.math import add
# → my@app@math:add(…)

Maps that merge

The one mutation-looking operator that is not mutation: |= merges a map into a new one via maps:merge/2.

user |= {'name': 'Ada'}
# maps:merge(User, #{name => 'Ada'})

Python's arithmetic

//, % and ** keep Python's semantics, not Erlang's; == coerces like Python, so 1 == 1.0 is true.

7 // -2   # -4, floored
-7 % 2    # 1, sign of divisor
1 == 1.0   # true

03 — parity

The same shape as Gleam.

Gleam compiles to Erlang abstract forms. So does squeal. When two programs mean the same thing, both compilers must emit the same forms — and the test suite checks exactly that, pair by pair, after normalising line annotations.

squeal
shapes.ee
class Point(StartingWithAtom):
    x: int
    y: int

def shift(p, dx):
    match p:
        case Point(x, y):
            q = Point(x + dx, y)
    q
gleam
shapes.gleam
pub type Point {
  Point(x: Int, y: Int)
}

pub fn shift(p: Point, dx: Int) {
  let q = case p {
    Point(x, y) -> Point(x + dx, y)
  }
  q
}
shapes.erl same abstract forms 
-export([shift/2]).

shift(P, Dx) ->
    Q = case P of
            {point, X, Y} -> {point, X + Dx, Y}
        end,
    Q.

Where Gleam has no equivalent — |= merge, .items(), non-exhaustive match, comprehensions — behaviour is pinned by ordinary tests instead: 19 pairs and 104 tests in total, run with pytest.

04 — notebook

Your Jupyter notebook, on the BEAM.

No custom kernel. Cells stay Python text, so plain Python autocomplete and linting keep working; a hook compiles each cell to Erlang and evaluates it in a persistent erl session.

  • Bindings survive between cells. Rebinding continues the X@N sequence, so running a cell twice is safe.
  • Definitions become named funs. Cells compile in shell mode, so def stays callable and recursive.
  • The Erlang shows through. Comprehensions print their equivalent as erl: [X * 2 || X <- squeal_iter(Xs)].

from users import with_name

user = {'age': 36}

Out [3]

05 — quick start

Four commands to a running module.

squeal is pre-release and runs from a checkout: Python 3.15 for the compiler, Erlang/OTP 29 to run what it builds.

Create the project tree

The module is the file path under src/.

my_app/
└── src/
    └── hello.ee

Write hello.ee

Ordinary Python. Strings in double quotes, atoms in single quotes.

def hello():
    "hi"

Build

Compiles src/** to abstract Erlang forms and .beam files.

$ python3.15 -m squeal build my_app
build/dev/erlang/my_app/ebin/hello.beam

Run it

It is a normal Erlang module from here on.

$ erl -pa my_app/build/dev/erlang/my_app/ebin -noshell \
    -eval 'io:format("~p~n", [hello:hello()]), halt().'
<<"hi">>
