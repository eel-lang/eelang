Eel Status: Alpha

A Python‑shaped BEAM language, inspired by Gleam.

Immutability, pattern matching, comprehensions and hierarchical modules — written in the Python you already know, compiled to Erlang abstract forms through the same pipeline Gleam uses.

Built on Gleam,
Eel follows these principles.

These are the directions the language is being built against. Some are already in the compiler; the rest are on the roadmap — the status section below says which is which.

01

IDE support

static analysis, first-class

A great static-analysis experience in the IDE is one of the goals — and the main target is PyCharm.

target · PyCharm
02

Great stdlib

batteries, with methods

A stdlib that is pleasant to use, with OOP-style methods on the core data structures.

config.get(key)
name.startswith(prefix)
03

Optional static typing

never mandatory

Static typing is fully optional. When you reach for it, it is there to make the code clearer and more expressive.

x: int   # optional
04

All data types equally

no second-class data

Maps, records, native records and the rest get the same level of support — and optional types make all of them convenient.

map · record · native record
05

OTP first-class

not an afterthought

Working with OTP matters as much as a good standard library.

OTP · first-class
06

Python ecosystem friendly

BEAM ↔ CPython

One of the tasks is to bring the BEAM and CPython ecosystems closer, and to popularise projects like Hornbeam.

hornbeam

Eel is a small language.
And it says no a lot.

Gleam is the reference for the semantics, Python for the syntax. Where the two disagree, Eel follows Gleam — and proves it with tests.

PropertyeelGleamPython
SyntaxPython 3.15ML-likePython
MutationNoNoYes
LoopsNoNofor / while
Pattern matchingYes, let it crashYes, exhaustivematch statement
TypesAnnotations as docsHindley–MilnerOptional hints
Compiles toBEAM, abstract formsBEAM, abstract forms—
Runtime dependencies00Interpreter + packages

Gleam 1.19 parity is enforced by 19 pairs of equivalent modules: both compilers must emit the same forms, compared after normalising line annotations. 104 tests in total, run with pytest.

Honest about the stage.
This is milestone one.

A compiler, a parity suite and a notebook. Types, static analysis and syntax beyond Python are not here yet — and the page says so.

Works today

  • doneCompiler from .ee to the BEAM Abstract Erlang forms, then compile:forms — the Gleam pipeline.
  • doneParity suite against Gleam 19 equivalence pairs, compared form by form.
  • doneJupyter notebook and persistent REPL Shell-mode cells over a live Erlang session.
